# Roster Creator 前端设计优化方案

> 目标：在保留现有品牌性格（暖色调 + Roo 袋鼠 + 圆润亲切感）的前提下，提升**信息密度、可扫读性、专业度与可用性**。
>
> 以下所有方案均为**建议**，未对任何文件做出改动。每条均标注：改造目标、涉及文件、具体做法、可选改法示例与改动量估算（S/M/L）。

---

## A. 数据页面表格化 / 排班网格（P0，改动量 L）

### 问题
排班本质是二维数据（周 × 员工 × 班次），当前却用"上下堆叠的卡片/select 流"呈现。`RosterDetailPage` 每个班次一行，靠 select 下拉选人，无法一眼扫读"哪天谁上什么班、哪些空位没填"。

### 改造目标
把排班详情从"纵向表单流"改为**排班网格（Roster Grid）**：

- 行 = 日期 / 班次，列 = 员工，单元格 = 该员工在该时段的状态（✓ 已分配 / 空 / 待确认）。
- 固定表头与首列，横向滚动。
- 空位用高亮占位（含未填标签色块），一眼可见缺口。

### 涉及文件
- `frontend/src/pages/RosterDetailPage.tsx`
- `frontend/src/components/RosterGrid.tsx`（新建）

### 可选改法示例（示意，非最终代码）
```tsx
// RosterGrid 示意：行=日期班次，列=员工
<div className="overflow-x-auto rounded-2xl border border-tan/15">
  <table className="w-full min-w-[56rem] border-collapse text-sm">
    <thead className="sticky top-0 bg-sand">
      <tr>
        <th className="sticky left-0 bg-sand px-3 py-2 text-left">日期 / 班次</th>
        {members.map(m => <th key={m.id} className="px-3 py-2">{m.name}</th>)}
      </tr>
    </thead>
    <tbody>
      {rosterShifts.map(rs => (
        <tr key={rs.id} className="hover:bg-white/70">
          <td className="sticky left-0 bg-sand px-3 py-2 font-medium">
            {rs.date} · {rs.shiftTemplate.name}
          </td>
          {members.map(m => {
            const a = assignments.find(x => x.rosterShiftId === rs.id && x.staffId === m.id);
            return <td key={m.id} className="px-3 py-2 text-center">
              {a ? '✓' : <button ...>空位</button>}
            </td>;
          })}
        </tr>
      ))}
    </tbody>
  </table>
</div>
```

### 同理建议推广
- `StaffListPage`、`GroupDetailPage`、`RosterListPage` 从卡片行改为标准**表格**（斑马纹、行悬停、表头排序占位）。
- 保留"列表 vs 卡片"切换视图的能力（可选，后期）。

### 验收标准
- 宽屏一眼能识别：某天缺几个人、谁被安排了几次。
- 空位有高亮，点击即可补人（跳转/内联下拉）。

## B. 内容容器宽度放开（P0，改动量 S）

### 问题
`AppShell` 主内容 `max-w-4xl`（约 896px）。宽屏下两侧大量留白，数据表/表单被压缩。

### 改造目标
按页面类型区分宽度，而非一刀切：

- 数据密集页（排班、员工、小组、班次模板）→ `max-w-6xl` / `max-w-7xl`。
- 表单/详情页 → `max-w-2xl` / `max-w-3xl`。

### 涉及文件
- `frontend/src/components/AppShell.tsx`（加一个 `width` 或 `wide` 属性，默认 `default`）
- 各密集数据页传入 `wide`

### 可选改法示例
```tsx
// AppShell 增加宽度档位
export function AppShell({ children, width = 'default' }: { children: ReactNode; width?: 'default' | 'wide' }) {
  // ...
  <div className={`mx-auto ${width === 'wide' ? 'max-w-7xl' : 'max-w-4xl'}`}>{children}</div>
}
```
```tsx
// 数据密集页
<AppShell width="wide">...</AppShell>
```

### 验收标准
- 1920px 显示器上，列表与排班网格能充分铺开，不留大面积白边。

## C. 后台装饰动效收敛（P0，改动量 M）

### 问题
`AmbientBackground` 在所有页面（含工作后台）都渲染：
- 3 个 `blur-3xl` 渐变色块（带 `blob-drift` 漂移动画）
- 6 片持续 `leaf-fall` 飘落的树叶

加上 `bob`、`ear-twitch`、`sunburst-in` 等，后台整天在动。对高频操作工具是干扰，也增加低端设备渲染负担。

### 改造目标
- **登录 / 注册 / 欢迎页**保留氛围感（可保留色块与叶子，甚至更突出）。
- **工作后台（AppShell 内）**：移除落叶动画、降低色块不透明度或改为静态，动效只留给状态反馈（加载、成功、切换）。

### 涉及文件
- `frontend/src/components/AmbientBackground.tsx`（加 `density`/`mode` 属性，如 `mode="ambient" | "subtle"`，或由 AppShell 传入 `subtle`）
- `frontend/src/components/AppShell.tsx`（后台用 `subtle`）

### 可选改法示例
```tsx
// AmbientBackground 增加节奏档位
export function AmbientBackground({ subtle = false }: { subtle?: boolean }) {
  const leafTone = subtle ? 'opacity-0' : '';
  return (
    <div aria-hidden="true" className="pointer-events-none fixed inset-0 -z-10 overflow-hidden">
      {/* subtle: 色块降透明度、去动画 */}
      <div className={`rounded-full bg-coral/15 blur-3xl ${subtle ? 'opacity-40' : 'motion-safe:animate-blob-drift'}`} />
      {/* subtle: 叶子直接不渲染 */}
      {!subtle && LEAVES.map(...)}
    </div>
  );
}
```
```tsx
// AppShell 内
<AmbientBackground subtle />
```

### 验收标准
- 后台页面静态或几乎静态，专业感提升；登录页氛围不减。

## D. 正文对比度与字号提升（P1，改动量 M）

### 问题
- 背景 `bg-sand`（米白）+ 大量 `bg-white/70` 半透明白卡片 → 文字"浮在雾上"。
- 正文大量 `text-sm` + `text-ink-soft` → 偏灰、对比度不足。

### 改造目标
- 正文基础字号 `text-sm` → `text-[15px]`（或视屏放宽到 15–16px）。
- 正文默认色用更深的 `ink`；`ink-soft` 只用于辅助说明。
- 卡片不透明度提升（`white/70` → `white/85` 或纯白），减少通透感带来的发灰。

### 涉及文件
- `frontend/src/components/AppShell.tsx`（取消 `bg-sand` 泛灰，正文色）
- `frontend/src/styles/ui.ts`（`inputBase`、`labelBase`、`listRow`、`cardBase`）
- `frontend/src/components/PageHeader.tsx`（描述色）

### 可选改法示例
```ts
// ui.ts 高对比调整示意
export const inputBase =
  'w-full rounded-2xl border border-tan/25 bg-white px-4 py-2.5 text-[15px] text-ink placeholder:text-ink-soft/45 outline-none transition focus:border-coral focus:ring-2 focus:ring-coral/30';
export const labelBase = 'mb-1.5 block text-xs font-semibold text-ink';
export const cardBase = 'rounded-[24px] border border-tan/15 bg-white/85 p-5 shadow-warm-sm';
```

### 验收标准
- 正文与背景对比度达标（可自测 ≥ 4.5:1）。

## E. 空状态组件化（P1，改动量 M）

### 问题
各列表空状态都只是一行文字，例如：
`还没有员工，点击右上角「创建员工」来添加一位吧。` 单调且引导弱。

### 改造目标
新建 `EmptyState` 组件，复用 Roo 吉祥物 + 说明 + 主操作按钮：

- 图标/插画（用 `KangarooMascot` 或线性插画）
- 一句说明
- 1 个主操作按钮（如「创建员工」）

### 涉及文件
- `frontend/src/components/EmptyState.tsx`（新建）
- 各列表页：`StaffListPage`、`GroupListPage`、`ShiftTemplateListPage`、`ResponsibilityListPage`、`RosterListPage`

### 可选改法示例（示意）
```tsx
<EmptyState
  icon={<KangarooMascot variant="badge" animated={false} className="h-16 w-16" />}
  title="还没有员工"
  description="创建第一位员工，开始安排团队"
  action={<Link to="/staff/new" className={btnPrimary}>创建员工</Link>}
/>
```

### 验收标准
- 空状态不再是"一行灰字"，而是有品牌、有引导、有行动的卡片。

## F. 状态值本地化（P1，改动量 S）

### 问题
`StatusPill` 直接渲染后端原始英文（`published` / `draft`），与全中文界面不协调，且颜色映射写死 `published`。

### 改造目标
- 建立 `status` → `{ label, color }` 映射表（中文文案 + 语义色）。
- 例如：`published → 已发布`（绿色）、`draft → 草稿`（灰色）、`sending → 发送中` 等。

### 涉及文件
- `frontend/src/components/StatusPill.tsx`

### 可选改法示例
```tsx
const STATUS_MAP: Record<string, { label: string; tone: string; dot: string }> = {
  published: { label: '已发布', tone: 'bg-eucalyptus/15 text-eucalyptus-dark', dot: 'bg-eucalyptus-dark' },
  draft:     { label: '草稿',   tone: 'bg-tan/15 text-tan', dot: 'bg-tan' },
};
export function StatusPill({ status }) {
  const s = STATUS_MAP[status] ?? { label: status, tone: 'bg-tan/15 text-tan', dot: 'bg-tan' };
  ...
}
```

### 验收标准
- 界面不再出现裸英文状态。

## G. 加载骨架屏（P1，改动量 M）

### 问题
`RosterDetailPage` 等加载态是一行 `加载中...` 文字，简陋且有跳动感。

### 改造目标
- 新建 `Skeleton` 组件（灰块 + 轻微 pulse 动画，尊重 `prefers-reduced-motion`）。
- 数据页初次加载渲染骨架屏：标题条 + 若干行/卡片的占位。

### 涉及文件
- `frontend/src/components/Skeleton.tsx`（新建）
- 各数据页替换 `加载中...`

### 可选改法示例（示意）
```tsx
<div className="space-y-4" aria-busy="true">
  <Skeleton className="h-8 w-48" />
  <Skeleton className="h-24 w-full rounded-2xl" />
  <Skeleton className="h-24 w-full rounded-2xl" />
</div>
```

### 验收标准
- 加载态不跳动，结构稳定，体验平滑。

## H. 导航激活态强化 + 图标化（P2，改动量 M）

### 问题
侧边栏是"纯文字 + 浅色激活背景"，层级偏平、可扫读性一般。

### 改造目标
- 为每个顶层导航项配一个线性图标（可用现有 dashboard 卡片的同类图标风格）。
- 强化激活态：左侧色条 + 淡色底 + 更明显的文字色。
- 保持 `min-h-[44px]` 触控标准与 `NavLink` 的 active 逻辑。

### 涉及文件
- `frontend/src/components/AppShell.tsx`

### 可选改法示例（示意）
```tsx
function navLinkClass({ isActive }) {
  return `relative flex min-h-[44px] items-center gap-2.5 rounded-xl px-3 text-sm font-medium transition ${
    isActive
      ? 'bg-coral-deep/10 text-coral-deep'
      : 'text-ink-soft hover:bg-white/60 hover:text-ink'
  }`;
}
// 激活时渲染左侧色条
{isActive && <span className="absolute left-0 top-1/2 h-5 w-1 -translate-y-1/2 rounded-full bg-coral-deep" />}
```

### 验收标准
- 导航项可快速识别，当前所在位置一目了然。

## I. 语义色系统收敛（P2，改动量 M）

### 问题
仪表盘四张卡用了 coral / eucalyptus / tan / dusk 四种强调色，再扩散到各页面容易"彩虹化"，难以快速理解"什么颜色代表什么含义"。

### 改造目标
- 定义语义色语义并约束使用：
  - `coral`（主操作 / 品牌主色）
  - `eucalyptus`（成功 / 已发布）
  - `red`（危险 / 删除）
  - 弱化 `tan`、`dusk` 在功能按钮上的使用（仅作品牌点缀）。
- 在 `styles/ui.ts` 里统一导出 `btn*` 时遵循此语义，避免页面散写。

### 涉及文件
- `frontend/src/styles/ui.ts`、`frontend/tailwind.config.js`（可选加语义别名如 `success` / `danger` / `brand`）

### 验收标准
- 界面中"颜色→含义"一致，新页面无需重新纠结配色。

## 建议实施顺序

1. **先做 P0（A、B、C）**：这三个最能改变"不好看 / 不像专业工具"的第一印象，且相互独立。
2. 再做 **P1（D、E、F、G）**：提升整体质感与完成度。
3. 最后 **P2（H、I）**：打磨品牌与规范统一。

每一条都可用 `styles/ui.ts` 中的共享令牌落地，避免散改，长期可维护。
